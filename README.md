# لوحة منهاجي

واجهة إدارة المحتوى والاشتراكات. HTML + CSS + JavaScript عادي، **بلا إطار عمل
وبلا خطوة بناء** — نفس مبدأ تطبيق الطالب ونفس توكنات التصميم.

## التشغيل

انقر نقرًا مزدوجًا على `index.html`.

**للتجربة:** `admin / admin` (كل الصلاحيات) · `teacher / teacher` (المحتوى فقط)

```bash
node test/smoke.js      # اختبارات المنطق والصلاحيات وسلامة البيانات
```

## أربع نقاط تستحق الانتباه

**١. زر «فرنسي» في محرّر الدرس.** يلفّ النص المحدّد بـ `<span class="fr">` فيُعزل
اتجاهيًا داخل الجملة العربية. بدونه تقفز علامات الترقيم إلى الطرف الخطأ — أكثر
عيب يتكرّر في المحتوى العربي/الفرنسي المختلط. علّم كل كلمة فرنسية به.

**٢. بطاقة «نواقص المحتوى» في لوحة المعلومات.** تحوّل إحساس «المحتوى ناقص» إلى
قائمة مهام محدّدة: أي درس بلا فيديو أو بلا أسئلة، مع زر يفتحه مباشرة.

**٣. «فكّ ارتباط الجهاز» في صفحة الطالب.** بلا بريد ولا كلمة مرور، هذا **مسار
الاسترداد الوحيد** للطالب الذي انكسر هاتفه. بدونه يبقى مقفلًا خارج اشتراكه
المدفوع. توقّع استعماله كثيرًا.

**٤. تقدير كلفة الفيديو.** صفحة الفيديوهات تحسب النقل الشهري المتوقّع لـ ١٠٠
طالب. احسم قرار الجودة **قبل** تصوير ٢٤ درسًا، لا بعده.

## الانتقال إلى Supabase

اللوحة اليوم تكتب في `localStorage`. البنية مصمّمة ليكون الانتقال محصورًا في
مكان واحد:

1. أنشئ مشروع Supabase وارفع الـ migrations من `C:\Users\Agha\syria-edu\supabase`.
2. في `js/store.js` استبدل `upsert` و`remove` باستدعاءات
   `supabase.from(...).upsert(...)` و`.delete()`، والقراءات بـ `.select()`.
3. استبدل `Store.signIn` بـ Supabase Auth، والأدوار بعمود `role` في `profiles`
   مع سياسات RLS تفرضها على السيرفر — **الحارس في `app.js` واجهة فقط، لا أمان**.
4. الفيديو: ارفع إلى Storage واحصل على رابط موقّع بدل محاكاة الرفع الحالية.
5. الأكواد: انقل التوليد إلى `tools/gen-codes` أو Edge Function، لتُخزَّن
   **مجزَّأة** لا صريحة.

> ⚠️ حارس الصلاحيات الحالي في الواجهة يمنع الوصول بصريًا فقط. الأمان الحقيقي
> هو RLS على قاعدة البيانات، وهي مكتوبة أصلًا في `syria-edu/supabase/migrations`.
