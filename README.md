# لوحة منهاجي

واجهة إدارة المحتوى والاشتراكات. HTML + CSS + JavaScript عادي، **بلا إطار عمل
وبلا خطوة بناء** — نفس مبدأ تطبيق الطالب ونفس توكنات التصميم.

## التشغيل

انقر نقرًا مزدوجًا على `index.html`. يحتاج اتصالًا فعليًا بالإنترنت — بخلاف
تطبيق الطالب، اللوحة ليست offline-first.

**الدخول:** بريد إلكتروني وكلمة مرور حقيقيان (Supabase Auth)، لا حساب تجريبي
بعد اليوم. لإنشاء حساب مدرّس أو أدمن:

```bash
cd ../syria-edu/tools
node create-staff/index.js --email sami@manhaji.app --password "..." \
     --name "الأستاذ سامي" --role teacher
```

```bash
node test/smoke.js      # اختبارات الأدوار وطبقة الشبكة وسلامة الترميز — بلا شبكة حقيقية
```

## الأقسام — أيّها متّصل بقاعدة بيانات حقيقية

| القسم | ماذا يفعل | البيانات |
|---|---|:--:|
| الدروس | كتب (courses) ← وحدات ← دروس + محرّر نصّي | **حقيقية** ✅ |
| بنك الأسئلة | جدول ومرشّحات ومحرّر الأنواع | **حقيقية** ✅ |
| لوحة المعلومات | مؤشرات + نواقص المحتوى | حقيقية جزئيًا* |
| الامتحانات | تجريبية ووزارية تُركَّب من البنك | وهمية (SEED) |
| الفيديوهات | مكتبة ورفع وربط + تقدير الكلفة | وهمية (SEED) |
| أكواد التفعيل | توليد دفعات وتصدير CSV | وهمية (SEED) — الحقيقي عبر `tools/gen-codes` |
| الطلاب | تقدّم + فكّ ارتباط الجهاز | وهمية (SEED) |

*لوحة المعلومات تحسب من `Store.get()` مباشرة، فأرقام الدروس/الأسئلة حقيقية
والباقي (فيديو، طلاب، أكواد) من SEED إلى أن تُوصَل تلك الصفحات في تمريرة لاحقة.

**لماذا نصف اللوحة فقط؟** الحاجة الفعلية كانت: يربط المدرّس أسئلة من البنك
بدرسه، ويعدّل شرحها ليطابق فيديوه. هذا يحتاج «الدروس» و«بنك الأسئلة» فقط.
وصل البقية (امتحانات، فيديو، أكواد، طلاب) عمل حقيقي منفصل — لا تفترض أنه
جاهز لأنه "يبدو" متصلًا في الواجهة.

## نقاط تستحق الانتباه

**١. زر «فرنسي» في محرّر الدرس.** يلفّ النص المحدّد بـ `<span class="fr">` فيُعزل
اتجاهيًا داخل الجملة العربية. بدونه تقفز علامات الترقيم إلى الطرف الخطأ.

**٢. محرّر الدرس يكتب HTML مباشرة، لا Markdown.** عمود `lessons.body_md` في
القاعدة كان يُفترض أن يحمل Markdown خام (تُنتجه أدوات الاستيراد من ملفات
`.md`)، بينما محرّر اللوحة `contenteditable` يُنتج HTML مباشرة. عند حفظ درس
من اللوحة، `body_html` (ما يعرضه التطبيق فعليًا) و`body_md` يصيران نفس
HTML — الدرس يبقى صحيحًا ومعروضًا كما يجب، لكن `body_md` لذلك الدرس تحديدًا
لم يعد Markdown "نقيًا" لو احتجت لاحقًا تصديره أو معالجته كنصّ مصدري.

**٣. ربط سؤال بدرس = بالضبط تغيير قائمة "الدرس" المنسدلة في محرّر السؤال.**
لا زرّ منفصل — بنك الأسئلة أصلًا فيه فلترة بالدرس وحقل "الدرس" بمحرّر كل
سؤال. افتح أي سؤال من البنك، اختر الدرس المستهدف، عدّل "الشرح" إن أردت،
احفظ. هذا ما طلبه المدرّس بالضبط.

**٤. الأدوار عبر `profiles.role` + RLS حقيقية على السيرفر،** لا حارس واجهة
فقط كما كان سابقًا. `is_staff()`/`is_admin()` (هجرة `20260802000200`) تفتحان
قراءة كل المحتوى (حتى المسوَّدات) وكتابته لـ `courses/units/lessons/
lesson_topics/questions/question_options` حصرًا. الامتحانات وأكواد
التفعيل وبيانات الطلاب تبقى خارج هذا النطاق عمدًا.

**٥. بطاقة «نواقص المحتوى» في لوحة المعلومات.** أي درس بلا فيديو أو بلا
أسئلة، مع زر يفتحه مباشرة — حقيقية الآن لأن الدروس والأسئلة حقيقية.

## البنية

```
index.html
css/  tokens.css (نسخة من تطبيق الطالب) · admin.css
js/
  ui.js           h() · أيقونات · أرقام عربية      ← مشترك مع تطبيق الطالب
  data/api.js     طبقة Supabase (نسخة مطابقة لآلية تطبيق الطالب، بدخول بريد/كلمة مرور حقيقيين)
  data/seed.js    بيانات وهمية — تخدم فقط الأقسام غير الموصولة بعد
  store.js        الحالة · الأدوار (RLS حقيقية) · تحويل الشكل db ↔ لوحة · upsert/remove حقيقيان لمعظم الجداول
  components.js   جدول · نافذة · حقول · تنبيه عائم · تنزيل CSV
  pages/          dashboard · content · questions · exams · codes · students · videos
  app.js          الهيكل · التوجيه · حارس الواجهة (RLS هو الأمان الحقيقي، هذا عرض فقط)
```

## وصل الأقسام المتبقّية (امتحانات · فيديو · أكواد · طلاب)

نفس نمط `content.js`/`questions.js`: في `store.js`، أضِف تحويل db↔لوحة
للجدول المعني، واجلبه ضمن `loadAll()`، ووجّه `upsert`/`remove` لتلك المجموعة
إلى دالة مخصّصة (راجع `upsertLesson`/`upsertQuestion` كمثال). أكواد التفعيل
تحديدًا **لا تُكتب أبدًا من هنا مباشرة** — تبقى حصرًا عبر `tools/gen-codes`
لأن الكود الصريح يجب ألّا يمرّ بمتصفح متصل بقاعدة بيانات، فقط عبر أداة سطر
أوامر تُخرجه كملف CSV مرة واحدة.
